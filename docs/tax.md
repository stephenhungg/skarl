# Tax-ready ledger

**Not tax advice — demo data.** This is an advisory ledger for Base Sepolia test-USDC contributor payouts. It does not compute or withhold real tax, collect real SSNs/TINs/identity documents, or file returns. Country notes are illustrative prompts for buyer review, not jurisdiction-specific determinations.

Contributors set a two-letter ISO country code and attest to `none`, `w9_on_file` or `w8ben_on_file` in the web contributor Earnings view (`/contribute/earnings`) or mobile Profile. Only those values and an update timestamp are stored in the tax profile; forms remain outside Skarl. Each change is audited. Form-on-file status is an attestation, not verification. Buyers can view the status for contributors to their orders; the finance agent cannot change it.

Every newly posted contributor payout journal records `usdValueAtPayment` in integer micro-USD and `taxYear` in UTC. The explicit demo assumption is **1 USDC = 1 USD**, not a price feed or a claim about historical exchange value. YTD values and payout counts are deterministic projections of posted payout journals, never a separate mutable counter. Pending obligations and unconfirmed transfers are not paid income. The order view identifies its contributors and shows their organization-wide YTD payouts; it does not imply a tax return is complete.

The deterministic auto-pay `policyApproval` gate sends an otherwise eligible payout to buyer review with `tax_form_missing` when the contributor has no form status. It creates no approval or dispatch. The owning buyer retains the existing reviewed-exception approval path. An `info_return_needed` flag is advisory and never blocks payment by itself. `SKARL_TAX_REPORTING_THRESHOLD_MICRO_USD` defaults to `600000000` ($600); thresholds change by year and jurisdiction, so this is configurable demo policy rather than a statement of current tax law. Illustrative country notes include possible information returns for US contributors and possible TDS considerations for IN contributors.

The buyer Ledger → Tax panel shows country, attested form status, YTD USD, payout count and flags. Its advisory CSV contains pseudonymous contributor IDs, country, form status, YTD USD, payout count and flags; it contains no names, tax IDs or wallet addresses. The CSV is generated by the read-only Convex tax summary query and downloaded by the dashboard.

Claude and Gemini receive typed read-only `taxSummary` and `contributorsNeedingForms` tools within the existing authorized order scope. They can draft a plain-language year-end summary or forms-needed note with the same **Not tax advice — demo data** label. They cannot set tax status, approve a payment or file anything.

Verification uses synthetic profiles, journals and policy scenarios. `pnpm scenario all` includes `tax_form_missing`; a live scenario requires an otherwise eligible payable from a contributor without a form. Source implementation and passing isolated tests do not establish a deployed tax flow, a successful inference call or a chain transfer. Deploy the updated Convex schema/functions and web/mobile clients separately; optionally set the threshold in Convex. This task does not deploy or change environment variables. Existing payout journals without tags are projected using their journal `effectiveAt` timestamp and exact payout amount under the same demo assumption; they are not rewritten.
